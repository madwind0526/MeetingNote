# Roadmap (다음에 할 일)

> 2026-08-17~18 세션에 걸쳐 사용자가 구술한 향후 기능 목록 + Wave 분류. 아직 대부분 구현 전 - 다음
> 세션 시작 시 이 문서부터 읽고, 어느 Wave부터 시작할지 사용자와 확인할 것.

## 확정된 설계 결정

- **사용자 인증**: Club(`C:\Claude\Club`)과 동일한 방식으로 확정(2026-08-18, AskUserQuestion으로 확인).
  `Member{id, knoxId, passwordHash(SHA-256), role: "admin"|"일반"}`, 로그인 화면, `localStorage`에 세션
  저장 - Club의 `authStore.ts`/`LoginView.tsx`/`vite.config.mts`의 로그인 라우트를 그대로 참고해서
  포팅. 댓글/회의록 삭제/게시판 글 삭제 권한이 전부 이걸 전제로 함.
- **미등록 발언자 처리(원래 열린 질문이었음)**: 사용자가 직접 답을 줬다 - 화자 매칭 우선순위는
  (1) 이 회의의 발표자/주관자/참석자로 등록된 사람들의 프로필 → (2) 그 외 시스템에 등록된 모든 프로필
  → (3) 그래도 없으면 "미등록"으로 표시. 미등록 화자를 사용자가 UI에서 실제 이름으로 수정하면, 그
  수정이 곧 그 이름으로 새 음성 프로필을 등록하는 트리거가 된다(별도 "프로필 등록" 버튼 없음).
- **수정 사전은 자동 이력 캡처가 아니라 수동 사전**: 원래 "STT 수정하면 이력을 자동으로 쌓는다"는
  아이디어였는데, 사용자가 약어 사전과 완전히 동일한 UI/구조(수동 등록 + 불러오기/내보내기/적용하기)로
  달라고 구체화함. 즉 "약어 사전"과 "수정 사전"은 컬럼만 다르고 나머지 메커니즘은 100% 동일한 두 개의
  치환 사전.
- **사전 적용 시점**: Audio→Text 변환 파이프라인 도중이 아니라, STT가 텍스트를 만든 **직후에** 별도
  후처리 단계로 사전(약어+수정) 적용. "적용하기" 버튼은 이미 분석 완료된 회의에도 소급 적용 가능해야
  함.

## Wave 계획

작업 성격이 완전히 다른 두 트랙으로 나뉜다 - **트랙 A(인증/권한/게시판)**와 **트랙 B(회의록 작성
파이프라인 고도화)**는 서로 의존성이 없으므로 순서를 바꿔서 진행해도 무방하다. 트랙 내부는 의존성 순.

### 트랙 A: 인증 · 권한 · 게시판

| Wave | 내용 | 의존성 / 참고 |
|------|------|----------------|
| **A1** | 사용자 인증 시스템 신규 구현 | Club의 `Member`/로그인/세션 패턴 그대로 포팅. `src/types/domain.ts`, 로그인 화면, `vite.config.mts` 라우트, Electron IPC(패키징 버전) 전부 신규. |
| **A2** | 회의록 삭제 권한 + 회의록 댓글 | A1 필요. 회의록에 `authorId` 필드 추가하고, 지금은 권한 체크 없이 아무나 삭제 가능한 걸 "본인 또는 admin만" 으로 제한(Club의 `canDeletePost` 패턴). 댓글은 Club의 `BoardComment` 구조 재사용. |
| **A3** | 게시판 신규 기능 | A1 필요. `C:\Claude\Club`의 `BoardPost`/`BoardComment`/`BoardView.tsx`/`boardStore.ts` 패턴을 거의 그대로 이식. 사이드바 왼쪽 상단 그룹의 제일 아래에 배치. 글 삭제는 작성자 본인 또는 admin만. |

### 트랙 B: 회의록 작성 파이프라인 고도화

| Wave | 내용 | 의존성 / 참고 |
|------|------|----------------|
| **B1** | 새 회의록 폼: 간사 필드 + 발표자/참석자 뱃지 | 독립적. 주관자 아래에 "간사" 필드 추가(`domain.ts`의 `Meeting`, `MeetingFormModal.tsx`). 발표자는 "발표1/발표2/..."(참석자 테이블에서 발표자 체크된 순서), 참석자는 "참석1/참석2/..." 뱃지를 어딘가에 표시(어느 화면에 노출할지는 착수 시 확인). 이 라벨들을 B4에서 그대로 재사용. |
| **B2** | 치환 사전 시스템 (약어 사전 + 수정 사전) | 독립적이지만 B4보다 먼저 있어야 그 사전이 이미 적용된 깨끗한 텍스트를 B4에 넘길 수 있음. 팝업 UI 1개를 컬럼만 다르게 재사용(약어: 약어/확장글/설명/삭제, 수정: 수정전/수정후/설명/삭제). 오름차순 정렬, 추가/불러오기/내보내기/적용하기 버튼. "적용하기"는 이미 분석된 STT 텍스트에도 소급 적용. 이후 모든 STT 분석은 텍스트 생성 직후 자동 적용. |
| **B3** | 화자 음성 프로필 영속화 | 독립적이지만 B4/B5가 정확한 실명을 쓰려면 먼저 있는 게 좋음. 위 "확정된 설계 결정" 참고 - 매칭 우선순위(이 회의 참석자 → 전체 프로필 → 미등록) + 미등록을 실명으로 고치면 자동 등록. `pyannote`의 `return_embeddings` 활용(로컬 WhisperX/Whisper CLI 경로만 - Naver Clova는 임베딩 미제공). |
| **B4** | 발표 자료 MD 컨버터 | 독립적 유틸리티. PDF/DOCX/PPTX → MD. 음성 파일과 발표 자료를 짝지을 수 있는 파일 네이밍 규칙을 같이 정함(예: 회의ID+Agenda번호 공유 prefix). |
| **B5** | 발표별 내용 정리 (질문/답변/의견/할일 구조화) | B1(뱃지 라벨) + B2(정제된 텍스트) + B3(정확한 화자 실명) + B4(MD 변환된 자료) 전부 필요. LLM으로 MD자료+STT텍스트를 합쳐 발표 내용 정리. 포맷: `(질문) 주관자-이름: ...` / `(답변) 발표1-이름: ...` / `(의견) 참석1-이름: ...` / `(할일) 발표1-이름: ...` (라벨-이름 형식, 라벨은 B1의 뱃지). |
| **B6** | 전체 회의록 합성 + 할일 통합 표 | B5 필요. 발표별 정리를 모아 정해진 포맷으로 전체 회의록 작성. 회의 중 나온 할일을 전부 모아 **할일 / 담당자 / 납기** 3컬럼 표로 별도 정리. |
| **B7** | 오디오 보관 정책 (원본 유지, 화자별 분리본은 완료 후 삭제) | B3(화자별 오디오 슬라이스가 실제로 존재해야 함) + B6(회의록 "완성" 상태가 삭제 트리거) 필요. 원본 오디오는 회의 자료와 함께 계속 보관, 화자별로 분리한 오디오 파일은 STT+회의록 작성이 다 끝나면 삭제. |

## 원래 있던 7개 항목과의 매핑

이전 세션(2026-08-17)에 기록했던 7개 항목은 전부 위 Wave에 흡수됨:
1. 약어 사전 → **B2**
2. 발표 자료+STT 결합 정리 → **B4 + B5**
3. 전체 회의록 합성 → **B6**
4. 회의 중 A/I 정리 → **B5(발표별) + B6(전체 통합 표)**
5. 미등록 발언자 처리 방안 → **설계 확정됨(위 참고), B3에서 구현**
6. 화자 음성 프로필 영속화 → **B3**
7. STT 수정 이력 재적용 → **B2(수정 사전으로 구체화됨)**

- **트랙 B(B1~B7) 전부 완료. 트랙 A + 트랙 B, 계획된 모든 Wave 완료.**

- **B6에서 확정**: 새 "합성" 기능을 만들지 않고 기존 "회의록 작성" 버튼을 프롬프트 레벨에서 개선하는
  쪽으로 확정(AskUserQuestion) - 새 API 라우트/UI 없음.
